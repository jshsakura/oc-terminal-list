# 모바일 하단 틈 — 하루를 태운 오진의 기록 (2026-09-02)

폰(iPhone, screen=852)에서 **강력 새로고침으로 들어오면 화면 아래에 빈 띠가 남고 퀵바가
떠오른다.** 키보드를 한 번 올렸다 내리면 정상으로 돌아온다. 주소를 쳐서 들어오면 멀쩡하다.

## 결론부터

**우리 코드가 아니다.** 리액트·폰트·서비스워커·우리 CSS 가 **하나도 없는** 빈 페이지에서도
똑같이 난다. 그 페이지에서 높이 지정 방식 네 가지(`position:fixed; inset:0` · `100dvh` ·
`100%` · `100svh`)를 나란히 놓고 봤는데 **넷 다 같은 자리에서 잘렸다.** 사파리에서만 나고
브레이브·오리온(같은 WebKit, 다른 크롬 UI)에서는 안 난다.

즉 **강력 새로고침이라는 진입 방식 자체**가 그 기기의 사파리에서 뷰포트를 잘못 잡는다.
CSS 로 넘을 수 있는 문제가 아니다.

다른 사이트에서 티가 안 나는 이유: 보통 사이트는 문서가 흐르고 스크롤되므로 뷰포트가 조금
짧아도 배경이 이어져 보이지 않는다. 이 앱은 **화면에 딱 맞춘 셸 + 바닥에 붙는 퀵바** 라
그 차이가 그대로 드러난다.

## 페이지 안에서는 감지할 수 없다

정상 상태와 밀린 상태에서 읽히는 값이 **전부 같다**(WS 로그로 실측):

```
vv=665 inner=665 cw=665 bh=665 off=0 pageTop=0 scrollY=0 screenY=0 gap=187
```

키보드로 고친 **직후**에도 한 글자도 안 달랐다. 그래서 조건부 보정도, 조건부 새로고침도
걸 수 없다. `screenY` 는 iOS 에서 늘 0 이라 판정에 쓸 수 없다.

## 오늘 시도해서 **안 통한** 것들 (다시 하지 마라)

| 시도 | 결과 |
|---|---|
| `--vvh` 를 상시로 걸기 | 값이 낡으면 그 자체가 띠가 된다 |
| 차이만큼 `padding-bottom` 으로 밀기 | 방향이 반대였다 — 내용은 상자 맨 위에서 시작한다 |
| `#root` 를 정적 배치로 | **더 나빠졌다.** 앱이 상단 크롬 뒤로 딸려 올라가 탭바가 화면 밖으로 |
| `height: 100dvh` / `100vh` | 변화 없음 |
| meta viewport 토글 · 1px 스크롤 · `display:none` 리플로우 | 변화 없음 |
| `viewport-fit=cover` 제거 · `interactive-widget` 제거 | 변화 없음 |

## 남는 대응

1. **강력 새로고침을 쓰지 않는다.** 배포마다 SW 캐시 버전이 각인되므로 평범한 새로고침으로도
   새 번들을 받는다([[project_sw_cache_stamp]]).
2. **홈 화면에 추가**(스탠드얼론). 주소창·툴바가 없으니 원인 자체가 없다.
3. 그래도 남는 띠는 **앱 배경색으로 칠해** 앱의 밑단처럼 보이게 한다(아래 규칙).

## 곁가지로 찾은 진짜 문제 — 폰트 preload 4.2MB

`index.html` 이 TTF 두 벌(각 2.1MB)을 `rel=preload` 로 받고 있었다. preload 는 로드 완료를
붙잡으므로 콜드 로드마다 4.2MB 가 임계 경로였다. woff2 로 바꾸고(2.1MB → 892KB) Bold 는
preload 에서 뺐다 — **4.2MB → 892KB**. 이 병과는 무관했지만 그 자체로 남길 값이 있다.
