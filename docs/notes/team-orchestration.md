# 팀 오케스트레이션 도우미 설계 (2026-11-19, 초안)

CLI 에 익숙하지 않은 사람도 "시킬 일" 만 말하면 되게 하는 기능이다. 사용자는 도우미 패널에
말하고, **팀장 세션**이 그 말을 맞는 **팀원 세션**에게 넘긴다. 팀원은 일을 끝내면 팀장에게
보고한다. 팀장도 팀원도 전부 터미널 속 에이전트(claude · codex · opencode)이고, 앱은 탭을
열고 글자를 옮기는 일만 한다.

## 지키는 것

- **백엔드는 LLM 을 부르지 않는다.** 판단은 전부 터미널 속 에이전트가 한다(아키텍처 규칙).
- **옵트인이다.** 로그인된 에이전트가 없으면 아무것도 돌지 않고, 기본 UX 는 그대로 범용 터미널이다.
- **숨는 것이 없다.** 패널은 팀장 세션 위에 얹은 쉬운 보기일 뿐이다. 닫으면 팀장이 실제로 받은
  프롬프트와 보고, 실행한 명령이 진짜 터미널에 그대로 있다.
- **팀장은 라우팅만 한다.** 코드를 읽거나 고치지 않는다. 결과를 요약해 대신 판단하지도 않는다.

## 전체 그림

```
✦ 도우미 패널 ──보기·입력──▶ 팀장 세션 (고정 탭, 진짜 tmux 터미널)
                                │ itl open: 탭 열기 · 브랜치 · 에이전트 띄우기 · 첫 지시문
                                ▼
                     팀원 세션들 (역할마다 탭 하나)
                                │ 끝나면 itl send lead '<Return 형식 보고>'
                                └──────────▶ 팀장 입력창으로 돌아온다
```

## 1. 화면

### 버튼

탭바 오른쪽 묶음, **⚙ 설정 바로 왼쪽**에 같은 크기(30px) 아이콘 버튼 하나(`components/TabBar.jsx`
의 오른쪽 그룹).

```
[탭들 …] │ ⌨ 빠른입력  📡 브로드캐스트  ✦ 도우미  ⚙ 설정
```

- 모바일에서도 보인다(폰에서는 `✦ ⚙` 두 개가 남는다). 폰에서 더 필요한 기능이다.
- 로그인된 에이전트가 없어도 버튼은 둔다. 숨기면 기능이 있는 줄 모른다.
- 맡긴 일이 돌고 있으면 버튼에 작은 점을 찍는다. 진행 목록으로 가는 입구가 이것 하나다.
- 아이콘 후보: lucide `Sparkles` 또는 `Wand2`.

### 패널

- 데스크톱: 오른쪽에서 터미널 **위로 덮는** frosted glass 패널(GlassModal 과 같은 `--modal-*` 변수).
  - ⚠️ **옆으로 밀지 않는다.** 터미널을 밀면 여닫을 때마다 모든 pane 폭이 바뀌고, tmux 가 창
    크기를 다시 맞추며 에이전트 화면이 다시 그려진다.
- 모바일: 아래에서 올라오는 시트.
- 구성(위에서 아래로):
  1. **맡긴 일** 목록: 역할 · 한 줄 요약 · 상태(작업 중 / 확인 필요 / 완료) · [탭으로 가기]
  2. **대화**: 사용자 말과 팀장 답 말풍선
  3. **입력창**과 전송 버튼
  4. 오른쪽 위: [터미널로 보기] · ⚙(팀 설정으로 바로 간다)
- 일을 넘기면 "작업 준비 완료. N번 탭에서 개발 담당이 시작했습니다" 를 잠깐 보여 주고, 패널이
  닫히면서 그 탭으로 넘어간다.

### 팀 설정

설정 모달 왼쪽 메뉴에 **"팀"** 항목을 더한다. 패널의 ⚙ 는 이 항목을 바로 여는 입구다(화면은 하나).

## 2. 팀 설정의 내용

| 항목 | 값 |
|---|---|
| 팀장 도구 | claude / codex (로그인된 것만 고를 수 있다) |
| 팀원 역할 표 | 스킬 이름 · 도구 · 작업 폴더 방식 |
| 자동 라우팅 | 켜기(바로 넘긴다) / 끄기(넘기기 전에 사용자에게 묻는다) |
| 보고 시점 | 완료 때만 / 막혔을 때도 |

### 역할은 awesome-opencode-skills 의 SKILL.md 를 쓴다

[jshsakura/awesome-opencode-skills](https://github.com/jshsakura/awesome-opencode-skills)
(VoltAgent/awesome-codex-subagents 의 SKILL.md 포트, 176개).

- SKILL.md 하나가 역할 하나다. 본문은 "부모 에이전트가 일을 나눠 주는" 구조를 전제로 쓰였고,
  끝의 `Return:` 칸(바꾼 것 · 확인한 것 · 남은 위험)이 그대로 보고 형식이 된다.
- 기본 표는 5~8개로 시작한다. 176개를 보여 주면 고르지 못한다.

  | 역할 | 스킬 | 도구 |
  |---|---|---|
  | 파악 | `code-mapper` | claude |
  | 개발 | `fullstack-developer` | codex |
  | 앱 | `flutter-expert` | codex |
  | 화면 수정 | `ui-fixer` | codex |
  | 리뷰 | `code-reviewer` | claude |

- frontmatter 의 `model` 은 무시한다. 무엇으로 띄울지는 역할 표가 정한다.
- `sandbox_mode` 도 강제 수단이 아니다(아래 "권한"). 읽기 전용 역할은 첫 지시문으로 "고치지
  않는다" 를 준다.
- **커밋을 고정해서** 이미지 빌드 때 받아 넣는다. 매주 동기화된 내용이 바로 들어오지 않게 한다.
- 우리 규칙(AGENTS.md: 브랜치에서 작업, PR 로만 병합, 폴링 금지, 4GB 테스트 상한)이 스킬보다
  위다. 훅이 계속 강제한다.

## 3. 로그인 확인과 자동 활성화

패널을 열 때 한 번 확인한다. 주기적으로 다시 보지 않는다. **도구를 실행하지 않고, 파일이 있는지만
본다.** 내용은 읽지 않고 밖으로 보내지도 않는다.

| 도구 | 보는 곳 |
|---|---|
| claude | `~/.claude/.credentials.json` 또는 `ANTHROPIC_API_KEY` |
| codex | `~/.codex/auth.json` |
| opencode | `~/.local/share/opencode/auth.json` |

- 하나라도 있으면 패널이 켜진다. 팀장은 로그인된 도구로 띄운다(claude 우선).
- 하나도 없으면 패널에 "claude 나 codex 에 로그인하면 여기서 바로 시킬 수 있습니다" 와 로그인
  명령만 보인다(워커의 첫 실행 안내와 같은 문구).
- 로그인 안 된 도구를 쓰는 역할은 목록에서 흐리게 표시한다.
- ⚠️ **파일이 있다고 로그인이 살아 있는 것은 아니다.** 띄운 뒤 인증 오류가 나면 패널을 다시
  "로그인이 필요합니다" 로 돌린다.

## 4. 권한: 승인 프롬프트 없이 띄운다

| 도구 | 띄우는 명령 |
|---|---|
| claude | `claude` (워커 managed settings 가 이미 권한을 다 준다) |
| codex | `codex --yolo` (워커 config.toml 도 이미 `never` + `danger-full-access`, 플래그는 보험) |
| opencode | 자동 승인. 플래그 이름은 구현 때 실제 버전에서 확인하고, 없으면 `opencode.json` 의 permission 으로 맞춘다 |

안전선은 플래그가 아니라 **컨테이너 격리 · branch-guard 훅 · 워커 이그레스 방화벽**이다.

## 5. 팀장 세션

- 고정 탭 하나에서 돈다. 패널을 처음 열 때 만들고, 그 뒤로는 같은 tmux 세션에 다시 붙는다.
- tmux 사용자 옵션 `@itl_role=lead` 를 새긴다(아래 `itl` 의 `lead` 별칭이 이것으로 찾는다).
- 첫 지시문에 들어가는 것: 팀 역할 표, `itl open` · `itl send` 사용법, "직접 고치지 말고 맡긴다",
  자동 라우팅 켜짐/꺼짐, 보고를 받으면 다음 역할(예: 리뷰)로 이어서 넘겨도 된다는 것.
- 패널의 입력은 `itl send lead '…'` 와 같은 길로 팀장 입력창에 들어간다(꼬리표 없이, 보낸 이는
  사용자).

## 6. 라우팅: "작업 준비 완료" 까지

팀장이 `itl open` 하나를 부르면 앱이 아래를 끝낸다. 사용자는 전송 버튼 하나만 누른다.

1. 맞는 작업 폴더(예: `/workspace/mood-clicker`)에서 새 탭을 연다.
2. 요청에 맞는 브랜치를 딴다(`fix/login-button-color`). main 에서 시작하지 않는다.
3. 역할의 도구를 승인 프롬프트 없이 띄우고 스킬을 넣는다.
4. **에이전트 입력창이 뜬 것을 확인한 뒤** 첫 지시문을 보내고 엔터까지 누른다. 터미널이 열린 것과
   에이전트가 입력받을 준비가 된 것은 다르다(`project_pane_typing_race`). `itl send` 의 확인 방식을 쓴다.
5. 팀장에게 결과(탭 주소, 작업 ID)를 돌려주고, 패널에 "작업 준비 완료" 를 띄운다.

막히면 그 단계의 이유를 말한다("로그인이 필요합니다", "커밋하지 않은 변경이 있어 브랜치를 만들지
못했습니다"). 그 상태로 "준비 완료" 를 띄우지 않는다.

팀원의 첫 지시문 = SKILL.md 본문 + 사용자 요청 + 끝에 붙는 한 줄:
"끝나면 Return 형식대로 `itl send lead '[작업 <ID>] …'` 로 보고한다."

## 7. 보고의 전달

- 팀원은 `itl send lead` 로 보고한다. 이미 있는 꼬리표(`[from 2.5 · 답장: itl send 2.5 '…']`)가
  붙어 팀장은 누가 보냈는지 안다.
- 백엔드는 보고의 `[작업 <ID>]` 를 보고 "맡긴 일" 목록을 완료로 바꾼다. 진행 중 상태는 이미 있는
  에이전트 상태 감지(working / permission / idle)를 그대로 쓴다. `permission` 이면 "확인 필요" 다.
- ⚠️ 주소 `1.2` 는 pane 을 닫으면 밀린다. 그래서 팀장을 숫자가 아니라 `lead` 로 찾는다.

## 8. 업데이트

- 패널을 열 때 각 도구의 버전을 비교한다. 깔린 버전은 설치 위치에서 읽고(npm 전역이면
  `package.json`, 네이티브 설치면 그 버전 디렉터리), 최신은 npm 레지스트리에서 받는다. 도구를
  실행하지 않는다.
- 새 버전이 있으면 도구 이름 옆에 [업데이트]. 누르면 **새 터미널이 열리고 업데이트 명령이 바로
  실행된다.** 진행과 오류가 터미널에 그대로 보인다.
- 돌고 있는 세션은 건드리지 않는다. 새로 띄우는 세션부터 새 버전이다.
- 워커에서는 `~/.local` 에 깔리므로 컨테이너를 다시 올려도 남는다.

## 9. 새로 만들 것

| 조각 | 내용 |
|---|---|
| `itl open` | `--role` `--cwd` `--branch` `--prompt-file`. 우편함(`@itl_outbox`)에 `op: open` 으로 싣는다 |
| `itl` 의 `lead` 별칭 | `@itl_role=lead` 인 pane 을 찾는다. 없거나 둘이면 거절한다 |
| 백엔드 open 처리 | 탭 상태에 탭 추가 → tmux 세션 생성 → 브랜치 → 에이전트 실행 → 준비 확인 → 첫 지시문 → SSE 로 프론트에 알림 |
| 맡긴 일 기록 | 작업 ID · 역할 · 탭 · 상태. 보고가 오면 완료 |
| 로그인 · 버전 확인 API | 파일 존재와 버전 문자열만 돌려준다 |
| 프론트 | 탭바 버튼, 패널, 설정 → 팀, 업데이트 버튼 |
| 워커 이미지 | 고정 커밋의 스킬 묶음, 팀장 첫 지시문 템플릿 |

### `itl open` 의 안전 규칙

- 팀 열쇠가 있는 pane 만 보낼 수 있다(지금 `itl send` 와 같은 `@itl_key` 검증).
- **띄우는 명령은 화이트리스트다.** 역할 표의 도구와 정해진 플래그만 실행한다. 페이로드에서 온
  임의 명령은 실행하지 않는다.
- 첫 버전은 **로컬 pane 만** 연다. 원격 호스트로 여는 것은 나중이다.
- 작업 폴더는 `validate_path` 로 워크스페이스 안으로 묶는다.

## 10. 대화 말풍선은 어디서 오나

TUI 화면을 긁어 말풍선을 만들지 않는다(깨지기 쉽다). 에이전트가 남기는 트랜스크립트(claude
`~/.claude/projects/*.jsonl`, codex 세션 jsonl)를 읽는다. `llm_usage/collect.py` 가 이미 같은
파일을 읽고 있으므로 그 파서를 재사용한다. 못 읽으면 말풍선 없이 "터미널로 보기" 만 둔다.

## 11. 단계

1. `itl open` · `lead` 별칭 · 백엔드 open 처리. 패널 없이 팀장 탭에서 직접 써 본다.
2. 탭바 버튼 + 패널(입력창, 맡긴 일 목록, 터미널로 보기). 로그인 확인.
3. 설정 → 팀, 스킬 묶음, 업데이트 버튼.
4. 트랜스크립트 말풍선.

각 단계는 워커(sdev/hdev)에서 팀원 계정으로 직접 눌러 확인한 뒤 다음으로 간다.

## 정하지 않은 것

- 팀장 하나에 팀원을 동시에 몇 명까지 둘지(워커 컨테이너는 메모리 6GB).
- 같은 저장소에서 팀원 둘이 동시에 일할 때 git worktree 로 나눌지, 브랜치만 나눌지.
- 팀장 세션이 길어지면(컨텍스트가 무거워지면) 언제 새로 띄울지.
